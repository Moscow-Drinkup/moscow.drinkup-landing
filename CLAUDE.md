# Moscow DrinkUp — соглашения проекта

Лендинг сообщества барных айти-митапов в Москве: <https://drinkup.moscow>

## Язык проекта — русский

Проект ведётся на русском языке. Это правило распространяется на всё, что
пишется людьми и агентами:

- комментарии в коде;
- спецификации, планы, ADR и прочая проектная документация;
- сообщения коммитов (тип и scope по Conventional Commits — на английском,
  описание — на русском);
- описания задач, issues и pull requests;
- собственные скиллы агентов, которые заводятся для этого проекта.

Английский остаётся там, где он часть кода или экосистемы: идентификаторы,
имена файлов и веток, типы Conventional Commits, названия зависимостей,
тексты из внешних библиотек. Термины и идентификаторы не переводятся:
пишем «слой `shared`», «fork-корректность», «SSG», а не «разделяемый слой».

Орфография — полная: буква «ё» там, где она нужна, кавычки-ёлочки в текстах,
тире вместо дефиса в качестве знака препинания.

## Стек

Проект переписывается с нуля в ветке `feat/rewrite`. Целевой стек:

- **Astro** — статическая генерация (SSG), файловый роутинг;
- **React** — острова интерактива внутри Astro-страниц;
- **Effector** — слой данных (`effector`, `effector-react`, при
  необходимости `effector-refetch` и `@effector/router`);
- **Gravity UI** — дизайн-система (`@gravity-ui/*`);
- **Feature-Sliced Design v2.1** — структура `src`;
- **pnpm** — менеджер пакетов.

Предыдущая версия сайта (Vite + React + `@gravity-ui/page-constructor` +
`react-router-dom` на `HashRouter`) лежит в ветке `main`.

## Команды

```bash
pnpm dev              # локальная разработка
pnpm build            # production-сборка
pnpm typecheck        # проверка типов
pnpm lint             # ESLint (+ правила effector, typed linting для src)
pnpm lint:css         # Stylelint
pnpm lint:fsd         # Steiger — архитектурный линтер FSD
pnpm format           # Prettier
```

Перед завершением работы над изменением прогоняются `typecheck`, `lint`,
`lint:css` и `lint:fsd`.

## Агентские скиллы

Скиллы устанавливаются через `npx skills add <owner/repo>` в `.agents/skills`
и фиксируются в `skills-lock.json`. Симлинки `.claude/skills` не трекаются —
восстанавливаются командой `npx skills experimental_install`.

Документация Astro доступна через MCP-сервер `astro-docs` (см. `.mcp.json`):
при работе с Astro сверяться с ним, а не с памятью модели.
